一句话先给结论：**头文件是“说明书”，lib 是“欠条”，dll 是“仓库”，cpp 是“工厂”**。用编译链接的流程看最清楚：

- **.cpp 源文件**：功能的实现本体。编译器把每个 .cpp 编译成一个 **.obj**（机器码，但还不完整——它调用的外部函数还是“空头支票”）
- **.h 头文件**：不是代码，是**声明清单**——“我有这么些函数、类，长这样，你随便调”。编译器看到你调 `inspect()` 时，靠 `#include "detector.h"` 知道这函数存在、参数对不对，**并不需要知道它怎么实现的**
- **.lib 静态库**：把一堆编译好的 .obj 打包成的“零件仓库”。链接时链接器直接把用到的机器码**复制进你的 exe**——之后 exe 自己就能跑，不依赖任何库文件，代价是体积大、更新库要重新编译整个程序
- **.dll 动态库**：程序运行时才加载的“外部仓库”。链接时只挂个“欠条”（导入库 lib 或运行时 LoadLibrary），**真正的代码在 dll 里，exe 启动后才去加载**。好处是多个程序共享一份、可以只换 dll 不重编 exe——你那个 AOI 设备换算法只替换 dll 就是这个套路





结论先说：**这条链不是一条线，是两条件。`.pt` 是唯一的源头，其余全是从它导出的"部署形态"。**

四个文件各是什么、起什么作用：

| 文件          | 是什么                                                       | 谁能用它                                                    | 作用                                                         |
| ------------- | ------------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------ |
| **`.pt`**     | PyTorch 权重，训练的直接产物（`best.pt`）                    | Python + PyTorch/ultralytics                                | 源头。能继续训练、能验证、能导出其他一切格式                 |
| **`.onnx`**   | 通用中间格式（Open Neural Network Exchange），描述的是**计算图**，不含框架信息 | Python（onnxruntime）、C++（ONNX Runtime）、也能再转 engine | 脱离 PyTorch 的"通用语"。跨平台，Windows/Linux/CPU/GPU 都能跑 |
| **`.wts`**    | 把 `.pt` 里的权重抽出来存成**纯文本**（只有数字，没有网络结构） | 只喂给官方 tensorrtx 之类的 C++ demo                        | 不是标准格式，是 YOLO 官方 C++ 仓库自定义的"搬运工"格式。C++ 端读它再手动搭网络 |
| **`.engine`** | TensorRT 编译后的**最终产物**，是针对**你那块具体 GPU + 具体 TensorRT 版本**编译出的二进制 | C++ / Python 的 TensorRT 推理，最快                         | 部署终点。不可移植——换一块 GPU 就得重新编译                  |

两条路线的区别：

1. **简单路**：`pt → onnx`，一条命令 `yolo export model=best.pt format=onnx`。Python 或 C++ 用 ONNX Runtime 直接推理，够用、通用。
2. **极限路（工业设备常用）**：`pt → wts`（或 onnx），再在目标机器上用 TensorRT 编译成 `.engine`。快 2–5 倍，但 engine 绑死 GPU 型号。

对应到你的场景：**Smart5 AOI 上位机是 C++，追求实时**，所以工业上多半走第 2 条路 —— 训练机上只留 `.pt` 和导出的中间格式，到部署机的 GPU 上现场编译出 `.engine`。

一个常见误区：**`.wts` 和 `.onnx` 不是上下游关系**，是平级的两条导出路径，看你的 C++ 代码吃哪个。现在官方 C++ 部署越来越倾向直接解析 onnx（省去手搭网络），wts 路线主要存在于老 tensorrtx demo 里。
